# FLASH / FM-DiT 单任务补充实验协议

本目录承接相邻 `flash-reproduction/` 中已经完成的 FLASH 复现。原始报告和数据不改写。本轮按照用户后续优先级，先补 FM-DiT、两种方法的早期闭环曲线，以及双方统一的稳定放置指标。独立场景划分与多训练 seed 属于后续实验，不与当前 40 条示范结果合并。

## 方法对齐

固定源码 commit：`f47e490f2b820f835d1b9145da3cdb3df69f50a0`。
任务：`libero_90.kitchen_scene1_put_the_black_bowl_on_the_plate`，MuJoCo / Franka。

两种方法复用完全相同的 40 条原始示范和文件哈希，39 条优化、参考 ID 49 的 1 条验证；seed 42、batch 32、15,000 次请求更新、原版 AdamW/cosine/EMA。FLASH 保留 ds4，FM-DiT 单独转换 ds1，保留 10 步推理。解析配置与 checkpoint 真实 global step 分别留存。

每种方法选取 2,500、5,000、7,500、10,000 更新的 EMA checkpoint，各做 50 次原版闭环评测，初始参考 ID 均为 0–49。对每一对场景核验初始状态 SHA256，不用训练 loss 代替成功率。统一使用物理 GPU 2，保存原始逐回合文字、视频和关节轨迹。原版评测任何一步满足几何判据就提前结束，最多 300 步。

先前 FLASH 10,000 checkpoint 的 GPU 3 结果保留为历史复现结果；本轮在 GPU 2 重新评测，统一曲线设备。不同 GPU 的微小数值差异可能在闭环中累积，因此不挑选更高的那个分数替代本轮成绩。

FLASH 参数覆盖与实际执行时刻并不完全一致，保留发布版行为。两者均使用 MuJoCo 原生位置 actuator。虽然上层 FLASH 标记发送速度目标，当前 handler 不消费该速度缓存，配置增益映射到 MJCF 的代码也被注释。补充观察器保存原生 `actuator_gainprm`、`actuator_biasprm` 和 `dof_damping`，最终逐项比较有效控制参数。不能据此实验声称速度前馈有效或网络模块的独立因果优势。

## 稳定放置

机器可读协议在首个稳定性试验之前固定，见 `configs/stable-placement-protocol.json`。使用两种方法的 10,000-step checkpoint、同一批 50 个初始状态，在原几何成功后继续让策略运行到 300 步（4.5 s），不强制张开夹爪。

每个动作后采样，以下条件必须同时连续保持至少 2 s：

- 原任务几何条件：碗盘 xy 中心距离小于 6 cm，碗高于盘的中心且高度差小于 3 cm。
- 两个手指实际位置均至少 3 cm，碗与手掌/手指的 MuJoCo contact 数组中没有接触对。
- 碗的世界系质心线速度不大于 0.02 m/s，角速度不大于 0.2 rad/s。

采样周期 15 ms，首尾跨度至少 2 s 需要 135 个连续样本（2.01 s）。这不是对每个 1 ms 物理子步的连续性证明，也不是永久稳定性证明。300 步总时限包含接近、放置和保持，因此较晚到达目标会剩余不足的保持时间，单独归为保持不足。新增判据保留较严格的夹爪开度要求，分数不代表所有可能的“已放置”定义。

速度直接使用原生 `mujoco.mj_objectVelocity(..., mjOBJ_BODY, ..., flg_local=0)`，记录世界朝向下的角速度及刚体惯性质心线速度，未使用 MetaSim 打包后的速度字段。接口依据：[MuJoCo 官方实现](https://github.com/google-deepmind/mujoco/blob/main/src/engine/engine_core_util.c)。

观察器用可审查的源码变换，仅插入读取、输出目录路由，并关闭几何成功提前退出。原始函数、变换后的函数和 diff 随每次试验保存。两种方法先用场景 0 对照同 GPU 原版提前结束，核验成功前动作和实际状态数组完全一致。首次几何成功时保存 RNG，继续执行结束后恢复，使后续回合不额外消耗 flow 随机数。环境仍沿用原版 reset，不声称更长回合后所有隐藏求解器状态都与提前结束评测相同。

原版成功率、继续执行中的“曾几何成功”、稳定放置分别报告；不同运行不合并成更大的独立样本数。失败原因先分“从未几何成功”“目标处从未释放”“连续稳定保持不足”，保留逐步数组供复算。

## 推理计时

训练完成后在同一张空闲 GPU 3 上交替方法顺序运行两轮，使用固定的参考 ID 49 原始频率 RGB/状态序列。每轮先预热至少 10 次实际模型调用，再同步 CUDA 计时 3,200 次控制调用。计时包括官方 `get_action` 的传输、预处理、观测历史、实际模型计算、动作重采样与字典转换，排除仿真、渲染、模型加载。分别报告实际模型调用和包含缓存调用的每控制步耗时；这个离线观察流计时不作为闭环成功结果。
